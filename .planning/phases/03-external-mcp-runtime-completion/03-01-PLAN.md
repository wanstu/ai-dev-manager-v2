Create new file `internal/app/mcp_health.go` in package `app`. Per D-04, health is derived from on-demand probe evidence, not persisted. Per D-02, no background health ownership.

Define types:

    type MCPHealthState string
    const (
        MCPHealthConfigured MCPHealthState = "configured"
        MCPHealthDisabled   MCPHealthState = "disabled"
        MCPHealthHealthy    MCPHealthState = "healthy"
        MCPHealthError      MCPHealthState = "error"
    )

    type MCPHealthStatus struct {
        MCPID     string         `json:"mcp_id"`
        State     MCPHealthState `json:"state"`
        Transport string         `json:"transport,omitempty"`
        ErrorKind string         `json:"error_kind,omitempty"`
        Message   string         `json:"message,omitempty"`
    }

Define `resolveEndpoint(endpoint string, headerRefs map[string]string) (string, map[string]string)`:
- Calls `os.ExpandEnv()` on the endpoint string — per D-03, this is the activation-boundary resolution.
- Calls `os.ExpandEnv()` on each HeaderRefs value.
- Returns resolved endpoint and resolved headers.
- This function is called ONLY at probe/connect time, never at status/inspect time.

Define `(s *Service) ProbeMCPHealth(ctx context.Context, environmentID, mcpID string) (MCPHealthStatus, error)`:
1. Look up the MCP ID in the global catalog. If not found → return `MCPHealthConfigured` with message "mcp not in catalog".
2. Check if the MCP is enabled for the Environment by inspecting `Environment.EnabledMCPIDs` — per D-06, Environment selection gates activation. If not enabled → return `MCPHealthDisabled`.
3. If enabled but Endpoint is empty → return `MCPHealthConfigured` with message "no endpoint configured".
4. Resolve endpoint and headers via `resolveEndpoint` — per D-03, secret resolution at activation boundary.
5. Create a bounded context (10s timeout) and attempt `connectExternalMCP(ctx, resolvedEndpoint)` — this reuses the existing Gateway helper. Since `connectExternalMCP` is in the `gateway` package and `ProbeMCPHealth` is in `app`, factor the probe-connection into a helper that the app package can call, OR move `connectExternalMCP` to a shared location, OR have `ProbeMCPHealth` accept a connect function. The simplest approach: have `ProbeMCPHealth` accept a `connectFunc func(ctx context.Context, endpoint string) (*mcp.ClientSession, error)` parameter that the Gateway layer injects. This avoids circular imports.
6. On connect success: attempt `session.ListTools(ctx, nil)` with 10s timeout.
7. On full success: close session, return `MCPHealthHealthy`.
8. On any failure: close session, classify error kind (`connection_refused`, `timeout`, `auth_failure`, `tool_list_failed`), return `MCPHealthError` with structured message. Per D-07, error message includes MCP ID and error kind but NEVER includes the resolved endpoint URL.
9. Per the Secret non-exposure rule: the resolved endpoint (which may contain real token values) is never returned in the status struct, error message, or logged anywhere.

In `internal/gateway/server.go`, add the `environment_mcp_status` Gateway tool — per D-06, enriching the existing tool surface:

    mcp.AddTool(server, &mcp.Tool{
        Name:        "environment_mcp_status",
        Description: "Probe health of one external MCP configured for the selected Environment.",
    }, func(ctx context.Context, _ *mcp.CallToolRequest, in EnvironmentMCPRuntimeInput) (*mcp.CallToolResult, any, error) {
        status, err := service.ProbeMCPHealth(ctx, in.EnvironmentID, in.MCPID, connectExternalMCP)
        if err != nil {
            return toolResult(nil, err)
        }
        return toolResult(status, nil)
    })

Note: `connectExternalMCP` is passed as the `connectFunc` parameter to avoid circular imports between `app` and `gateway`. The `app.ProbeMCPHealth` signature accepts this as a dependency-injected function.

Since `ProbeMCPHealth` requires a `connectFunc`, the tests inject a mock connect function or use a real `httptest.NewServer`. For healthy/error state tests, use a real `httptest.NewServer` mock external MCP server (same pattern as existing `TestGatewayUsesOnlyEnabledConfiguredExternalMCPAndSkillRuntime`).
