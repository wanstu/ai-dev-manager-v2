**1. Management service** — add `MCPHealth` method to `internal/management/service.go`:

    func (s *Service) MCPHealth(environmentID, mcpID string) (app.MCPHealthStatus, error) {
        return s.app.ProbeMCPHealth(context.Background(), environmentID, mcpID, nil)

Note: The `nil` connectFunc here needs to be resolved — since `ProbeMCPHealth` accepts a connect function, and the management layer does not import `gateway`, either:
- Option A: `ProbeMCPHealth` accepts a `connectFunc` parameter, and management passes a default implementation (duplicated connection logic) or a shared helper in the `app` package.
- Option B (recommended): Move the actual HTTP connection creation into the `app` package (e.g., `internal/app/mcp_connect.go`) so both `app.ProbeMCPHealth` and `gateway.connectExternalMCP` use the same shared function. This avoids circular imports AND avoids code duplication.

Recommended approach: Create `internal/app/mcp_connect.go` with:

    func ConnectExternalMCP(ctx context.Context, endpoint string, headers map[string]string) (*mcp.ClientSession, error)

This function creates the `mcp.Client`, builds a custom `http.Client` with a header-injecting round-tripper if headers are non-empty, connects via `StreamableClientTransport`, and returns the session. The error message does NOT include the endpoint URL.

Then both `app.ProbeMCPHealth` and `gateway.connectExternalMCP` delegate to this shared function. The gateway's `connectExternalMCP` becomes a thin wrapper or is replaced entirely by calls to `app.ConnectExternalMCP`.

Update `internal/app/mcp_health.go`'s `ProbeMCPHealth` signature to remove the `connectFunc` parameter and use `ConnectExternalMCP` directly.
